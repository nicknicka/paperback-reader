# 本地桌面小说阅读器综合计划

## Summary

构建一个跨平台 Tauri 桌面小说阅读器。第一次打开进入极简书库，用户可导入 `.txt`、`.doc`、`.docx` 本地小说文件，无账号、无云同步、无在线书源。核心体验是高质感书库、稳定分页阅读、自动目录、阅读排版台和本地进度恢复。

设计方向：极简电子纸 + 现代文学阅读器。像 Kindle 与 iA Writer 的克制结合，靠排版、留白、纸色、封面版式和低干扰控件建立质感，不做仿古皮肤，也不做网页书站。

## Key Changes

- 书库：首页只展示本地书籍、导入入口、最近阅读状态；无登录、推荐流、广告、社交内容。
- 导入：第一版支持 `.txt`、`.doc`、`.docx`；文件复制到本地应用数据目录，不上传服务器。
- DOC 兼容：`.doc` 能解析就导入，失败时优雅提示并建议转为 `.docx` 或 `.txt`，不为老格式牺牲整体复杂度。
- 自动封面：无真实封面时，根据书名、作者或文件名自动生成文字封面，风格统一、安静、有书籍质感。
- 阅读：默认横排中文、单页居中、分页翻页；正文区域无下拉滚动条，超出内容进入下一页。
- 自适应分页：窗口尺寸、字号、行距、页宽、字体变化后实时重新分页，并尽量保持当前阅读位置。
- 目录：必须支持自动目录；TXT 用章节规则识别，DOC/DOCX 优先读取标题结构，失败时降级为位置浏览。
- 排版台：提供字号、行距、页宽、字体、纸色、夜读主题、段落间距设置。
- 进度：保存书籍 ID、章节 ID、页码、排版设置、最近阅读时间，关闭重开后恢复。
- 后续能力：EPUB 放入 v1.1 规划，不进入第一版核心范围。

## Implementation Notes

- 技术栈：Tauri + React/Web UI；使用 Tauri Dialog 做文件选择，Tauri File System 做本地读写。
- TXT 解析：处理常见文本编码，按“第 X 章”等规则切分章节，无法识别时按段落块建立位置索引。
- DOCX 解析：提取正文、标题和段落结构，不保留 Word 原始视觉样式，只转换为阅读器内部结构。
- DOC 解析：作为兼容路径处理，失败不阻断其他导入功能。
- 分页引擎：用隐藏测量容器计算每页内容容量，阅读容器固定高度并 `overflow: hidden`，禁止正文滚动条。
- UI 布局：书库为简洁封面网格或低密度列表；阅读页为中央纸页、左侧目录抽屉、右侧排版台抽屉、底部轻量进度。
- 视觉规则：浅色电子纸主题和夜读主题统一使用低对比背景、清晰正文、少量控件；不使用装饰性渐变、厚重卡片、仿古纹理或营销页布局。

## Test Plan

- 首次打开显示空书库，导入入口明确。
- TXT、DOCX 能导入、生成书库条目、自动封面、目录和分页正文。
- DOC 解析失败时应用不崩溃，提示清晰。
- 长书名、短书名、无作者信息的自动封面都不破版。
- 调整窗口、字号、行距、页宽后重新分页，正文无垂直滚动条。
- 翻页、目录跳转、键盘操作、关闭重开恢复进度都正确。
- 浅色和夜读主题下，正文、按钮、目录、排版台均可读。
- 长篇小说导入和翻页保持流畅，不因重新分页造成明显卡顿。

## Assumptions

- 第一版不做账号、云同步、在线书源、批注、划线、全文搜索、推荐系统、移动端。
- 默认横排中文、单页居中，不做双页摊开和竖排。
- `.doc` 是兼容目标，不承诺所有文件 100% 成功。
- EPUB 暂不进 MVP，但架构上保留后续新增导入格式的位置。
